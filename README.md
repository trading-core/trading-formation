# trading-formation

Orchestrates the frontend + backend services for local development. Service env files
and a host-mode `Makefile` are generated by Ansible from a small set of declarative
YAML files; Docker Compose runs the stack; an optional proxy mode lets you swap any
single backend container for a host-side `go run` while the rest stay in compose.

## Layout

```
trading-formation/
  playbook.yml         entry point — loads vars, runs each service's formation.yml
  secrets.yml          ansible-vault encrypted (token, broker creds, alpaca keys)
  services.yml         per-service host/port — { container: ..., local: ... }
  resources.yml        redis, postgres, logs, stores, storage (mode-aware)
  library.yml          secrets, apis, clients, public_clients
  tasks/
    render-service.yml renders container .env + collects local env into Makefile
    render-env.yml     single-mode render (used by frontend)
  templates/
    service.env.j2          KEY=VALUE per line
    Makefile.j2             per-service `run-<svc>` targets with env inlined
    docker-compose.yml.j2   compose definition derived from services.yml + resources.yml
  run-services.sh      compose + proxy orchestrator
  docker-compose.yml   generated, gitignored
```

Each backend service declares only what it consumes:

```yaml
# trading-backend/cmd/account-service/formation.yml
- name: Render account-service
  include_tasks: "{{ playbook_dir }}/tasks/render-service.yml"
  vars:
    service_name: account-service
    cmd_dir: cmd/account-service
    env_dest: backend/account-service/.env
    resources:
      secrets: [token, broker_credentials]
      logs:    [account_event_log]
      apis:    [trading_api, frontend]
```

The kinds (`secrets`, `logs`, ...) are top-level vars in `library.yml` / `resources.yml`.
Each named resource maps to a dict of env-var key/value pairs.

## Prerequisites

- **Docker** (Desktop on Windows/Mac, Engine on Linux)
- **Ansible** — for rendering env files and the Makefile
- **GNU Make** — only needed if you want proxy mode (`make run-<svc>`)
  - Linux/Mac: usually preinstalled
  - Windows: `winget install ezwinports.make` (or `choco install make`), then restart the shell so `make` is on `PATH`

## Setup

1. Edit `secrets.yml` (encrypted via ansible-vault).
2. Render env files and the host-mode Makefile:

   ```bash
   ./run-services.sh render
   ```

   This runs the playbook and produces:
   - `docker-compose.yml` (the compose stack — gitignored)
   - `backend/<service>/.env` for each backend service
   - `frontend/.env`
   - `../trading-backend/Makefile` with `run-<service>` targets (host mode, gitignored)

   For a single service: `ansible-playbook playbook.yml --ask-vault-pass --tags account-service`.

3. Bring up the stack:

   ```bash
   ./run-services.sh start    # build + up -d
   ./run-services.sh up       # up -d (no rebuild)
   ./run-services.sh kill     # down --remove-orphans
   ./run-services.sh delete   # purge containers, images, volumes
   ```

   Both `start` and `up` honor `proxy.conf` if it exists — see [Proxy mode](#proxy-mode-host-side-service-for-debugging).

4. Access:
   - Frontend: http://localhost:3000
   - account-service: http://localhost:9000
   - stock-screener: http://localhost:8080
   - bot-service: http://localhost:8081
   - reporting-service: http://localhost:8082
   - storage-service: http://localhost:8083
   - journal-service: http://localhost:8084
   - authentication-service: http://localhost:9100
   - Redis: localhost:6379, Postgres: localhost:5432

## Proxy mode (host-side service for debugging)

To iterate on a single backend service on the host while the rest of the stack runs
in docker:

```bash
./run-services.sh proxy        # seeds proxy.conf and opens it in $EDITOR
./run-services.sh start        # (or `up`) — starts compose, replaces flagged services
                               # with socat proxies, prints the make commands to run
./run-services.sh status       # which proxies are running
./run-services.sh kill         # tears down both compose and proxies
```

`proxy.conf` is a sourced shell file:

```sh
ACCOUNT_SERVICE=0
STOCK_SCREENER=0
AUTH_SERVICE=0
BOT_SERVICE=1     # run on host
REPORTING_SERVICE=0
STORAGE_SERVICE=0
JOURNAL_SERVICE=0
```

When `up` runs:
- The flagged service is excluded from `docker compose up`.
- A socat container with `--network-alias <service>` is started so dockerized siblings
  reach the host process via `<service>:<container_port> -> host.docker.internal:<container_port>`.
- The script prints the `make` command for each flagged service. Run each in its own
  terminal (kept separate so logs and Ctrl-C stay sane during debugging):

  ```bash
  make -C ../trading-backend run-bot-service
  ```

  The Makefile target inlines the local-mode env (`localhost`-routed), so the host
  process talks back to dockerized siblings via published ports.

**Caveat**: the host process must bind to the same port docker-compose lists as the
container port (e.g. bot-service on 8080, not 8081). Two host processes claiming the
same container port can't run at once.

## Adding a service

1. Add an entry to `services.yml` with `container` + `local` host/port and a `compose`
   block (published_port, memory, depends_on, volumes).
2. If it needs a new resource kind (e.g. a new event log group), extend `resources.yml`
   or `library.yml`.
3. Add `cmd/<service>/formation.yml` declaring its `resources`.
4. Wire its env-render task into `playbook.yml`.
5. Add it to the `SERVICES` array in `run-services.sh` if it should participate in
   proxy mode.

`docker-compose.yml` is regenerated automatically from `services.yml` + `resources.yml`
on the next `./run-services.sh render`.

## Secrets

`secrets.yml` is encrypted with ansible-vault. To edit:

```bash
ansible-vault edit secrets.yml
```

The rendered `Makefile`, `.env` files, and `docker-compose.yml` are generated artifacts
and are gitignored. `proxy.conf` is also gitignored.
