# trading-formation

Orchestrates the frontend and backend services for both local development and server deployment. Service env files and a host-mode `Makefile` are generated by Ansible from declarative YAML files. Docker Compose runs the stack. An optional proxy mode lets you swap any single backend container for a host-side `go run` while the rest stay in compose.

## Layout

```
trading-formation/
  playbook.yml              entry point — loads vars, runs each service's formation.yml
  secrets.yml               ansible-vault encrypted (token, broker creds, alpaca keys)
  services.yml              domains, per-service host/port
  resources.yml             redis, postgres, logs, stores, storage (mode-aware)
  library.yml               secrets, apis, clients, public_clients, local_public_clients
  tasks/
    render-service.yml      renders container .env + collects local env into Makefile
    render-env.yml          single-mode render (used by frontend)
  templates/
    service.env.j2          KEY=VALUE per line
    Makefile.j2             per-service run-<svc> targets with env inlined
    docker-compose.yml.j2   compose definition derived from services.yml + resources.yml
    traefik-static.yml.j2   Traefik routing for both server and local domains
  backend/
    Dockerfile              shared multi-stage Go build for all backend services
  frontend/
    Dockerfile              Next.js multi-stage build
  scripts/
    build.sh                sync secrets → push → stream build log → notify
    deploy.sh               docker compose up -d on server with pre-built images
  run-services.sh           compose + proxy orchestrator
  docker-compose.yml        generated, gitignored
```

Each backend service declares only what it consumes:

```yaml
# trading-backend/cmd/account-service/formation.yml
resources:
  secrets: [token, broker_credentials]
  logs:    [account_event_log]
  apis:    [trading_api, frontend]
```

The kinds (`secrets`, `logs`, `apis`, ...) are top-level vars in `library.yml` / `resources.yml`. Each named resource maps to a dict of env-var key/value pairs.

## Prerequisites

- **Docker** (Desktop on Windows/Mac, Engine on Linux) with WSL2 integration enabled
- **Ansible** — for rendering env files and the Makefile
- **GNU Make** — for proxy mode (`make run-<svc>`)
- **Go 1.25+**, **Node.js LTS**, **Python 3.10+**

## Domains

Two environments, two sets of domains:

| | Frontend | API |
|---|---|---|
| **Server** | `trading-core.local` | `api.trading-core.local` |
| **Local dev** | `trading-core.localhost` | `api.trading-core.localhost` |

**Server domains** require dnsmasq running on the server and your router DNS pointed at it. See [Server deployment](#server-deployment).

**Local dev domains** (`.localhost`) resolve to `127.0.0.1` natively in all modern browsers — no hosts file or DNS setup needed.

## Local development

### 1. Render env files

```bash
./run-services.sh render
```

Produces:
- `docker-compose.yml`
- `backend/<service>/.env` for each backend service
- `frontend/.env` — used in the Docker image build (server domains)
- `frontend/.env.local` — used by Next.js locally (`.localhost` domains, takes priority over `.env`)
- `../trading-backend/Makefile` with `run-<service>` targets

For a single service: `ansible-playbook playbook.yml --ask-vault-pass --tags account-service`

### 2. Bring up the stack

```bash
./run-services.sh start    # build + up -d
./run-services.sh up       # up -d (no rebuild)
./run-services.sh kill     # down --remove-orphans
./run-services.sh delete   # purge containers, images, volumes
```

### 3. Access

All traffic goes through Traefik on `:80`:

| Service | Local URL | Container port |
|---|---|---|
| frontend (Next.js) | http://trading-core.localhost | 3000 |
| account-service | http://api.trading-core.localhost/accounts/v1 | 9000 |
| stock-screener | http://api.trading-core.localhost/stock-screener/v1 | 8080 |
| authentication-service | http://api.trading-core.localhost/auth/v1 | 9100 |
| bot-service | http://api.trading-core.localhost/bots/v1 | 8081 |
| reporting-service | http://api.trading-core.localhost/reports/v1 | 8082 |
| storage-service | http://api.trading-core.localhost/storage/v1 | 8083 |
| journal-service | http://api.trading-core.localhost/journal/v1 | 8084 |
| redis | localhost:6379 | 6379 |
| postgres | localhost:5432 | 5432 |

## Server deployment

The server runs the stack at `192.168.1.45` with dnsmasq providing DNS for the local network.

### DNS setup (one-time)

dnsmasq runs on the server and resolves `trading-core.local` and `api.trading-core.local` for all devices on the WiFi. Point your router's primary DNS at `192.168.1.45` (secondary: `1.1.1.1`).

### Deploy workflow

```bash
# After secrets change (re-render first):
./run-services.sh render

# Build and deploy all services:
./scripts/build.sh
./scripts/deploy.sh

# Rebuild a single service:
./scripts/build.sh storage-service
./scripts/deploy.sh
```

`build.sh` syncs secrets to the server, pushes the repo, and streams the Docker build log live. A Windows desktop notification fires when the build is ready.

### Server URLs

| Service | URL |
|---|---|
| frontend | http://trading-core.local |
| API services | http://api.trading-core.local/<path_prefix> |
| storage (files) | `/opt/trading-storage` on server |

## Proxy mode (host-side service for debugging)

To iterate on a single backend service on the host while the rest of the stack runs in Docker:

```bash
./run-services.sh proxy        # seeds proxy.conf and opens it in $EDITOR
./run-services.sh start        # starts compose minus flagged services
./run-services.sh watch        # keeps Traefik routes in sync with host process ports
./run-services.sh status       # which proxied services have an active port file
./run-services.sh kill         # tears down compose and clears proxy routes
```

`proxy.conf` is a sourced shell file:

```sh
ACCOUNT_SERVICE=0
STOCK_SCREENER=0
AUTH_SERVICE=0
BOT_SERVICE=1     # run on host
REPORTING_SERVICE=0
STORAGE_SERVICE=0
JOURNAL_SERVICE=0
```

When a service is flagged, it is excluded from `docker compose up` and a Traefik dynamic route is written under `traefik-dynamic/<svc>.yml` routing `api.trading-core.localhost/<prefix>` → `host.docker.internal:<ephemeral_port>`. Run each flagged service in its own terminal:

```bash
make -C ../trading-backend run-bot-service
```

## Adding a service

1. Add an entry to `services.yml` with `scheme`, `path_prefix`, `container` host/port, and a `compose` block. The YAML key (underscored) must match the `trading-backend/cmd/` directory name with `_ → -`.
2. If it needs a new resource kind, extend `resources.yml` or `library.yml`.
3. Add `cmd/<service>/formation.yml` declaring its `resources`.
4. Wire the render task into `playbook.yml`.
5. Add to the `SERVICES` array in `run-services.sh` for proxy mode support.

## Secrets

`secrets.yml` is encrypted with ansible-vault:

```bash
ansible-vault edit secrets.yml
```

The rendered `Makefile`, `.env` files, `docker-compose.yml`, and `proxy.conf` are generated artifacts and are gitignored.
